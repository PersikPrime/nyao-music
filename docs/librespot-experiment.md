# Spotify (librespot), эксперимент в nightly

Первый вариант — только ПК: macOS Intel / Apple Silicon и Windows x64.
Нужен полный установщик 0.8.96 или новее: нативный исполняемый файл не входит в быстрые обновления.
Флаг выключен по умолчанию. Обычный Spotify через SDK остаётся отдельной привязкой.

## Как проверить

1. Войти в аккаунт Nyao с отметкой разработчика.
2. Настройки → Разработчик → Флаги → Spotify (librespot).
3. В сервисах под обычным Spotify появится Spotify (librespot).
4. В своём приложении Spotify Developer Dashboard добавить Redirect URI
   `http://127.0.0.1:43820/spotify-callback`. Можно использовать свой существующий Client ID.
5. Сохранить Client ID и нажать «Войти». Вход открывается в обычном браузере через PKCE.
6. Нужен Spotify Premium. После проверки аккаунта и соединения включается нативный движок.
7. Проверить звук, паузу, перемотку, громкость, следующий/предыдущий трек,
   автоматический переход, переключение на другой сервис, выключение флага и перезапуск приложения.

Кнопка «Вернуться к обычному Spotify» переключает движок, сохраняя обе привязки.
Выключение флага закрывает процесс librespot. Выход из Nyao также останавливает его.
При неподдерживаемом аккаунте или отказе Spotify показывается ошибка.

## Что меняется

Звук воспроизводит отдельный локальный процесс на librespot 0.8.0 с Rodio.
Официальное приложение Spotify не требуется; этот процесс не является пультом другого плеера.
Для поиска, библиотеки и лайков остаётся Spotify Web API со своим Client ID.
Поэтому ограничения Web API, Premium и региональная доступность остаются актуальными.

Очередь и медиаклавиши используют существующий транспорт Nyao; HTML audio ведёт
таймер, а его позиция сверяется с нативным движком. Эквалайзер Web Audio и эффекты
на HTML audio не обрабатывают нативный звук. Android пока использует прежний путь.

## Хранение и диагностика

Отдельные ключи `librespot_spClientId`, `librespot_spTokens`, `librespotDeviceId`
находятся в локальном защищённом хранилище. Для нового входа требуется системное шифрование.
Токен передаётся дочернему процессу только через stdin, без аргументов запуска.
Встроенный worker не сохраняет токены, аудиокэш, пароли или диагностические файлы;
stderr зависимостей не собирается. Диагностика показывает версию и состояние движка.

Флаг и запуск проверяются в main процессе: nightly, действующий аккаунт Nyao,
подтверждённая сервером роль разработчика. Наличие скрытого пункта в интерфейсе не даёт доступа.

## Проверки

`npm test` проверяет изоляцию привязок, флаг, отмену старого запуска, паузу,
состояния, падение worker и несовместимость быстрых обновлений со старыми установщиками.
CI компилирует Rust worker, выполняет его unit-тесты и smoke-тест IPC без аккаунта.
Сборка приложения и эти тесты не подтверждают реальное воспроизведение с аккаунтом Spotify:
это проверяется вручную по списку выше на устройстве с Premium.
