# 6. Моя волна

Волна — самая «умная» и самая хрупкая часть приложения. Здесь меньше всего кода, но больше всего
решений, которые легко незаметно сломать. Перед правками прочитайте главу целиком.

## Две половины

```
WaveMixer (src/main/wave.js)            WavePolicy (src/main/wave-policy.js)
— откуда брать кандидатов                — что из них поставить в очередь
  лайки всех сервисов                       доли «недавнее / любимое / новое»
  «Моя волна» Яндекса (rotor)               баланс сервисов (Яндекс ↔ остальные)
  радио YT, похожее SC, рекомендации VK     без повторов, без одного исполнителя подряд
  поиск по исполнителю затравки             дизлайки, «уже слышал» за 14–30 дней
  (nightly) своя волна Nyao с сервера       случайность, но в рамках квот
```

**Mixer собирает, Policy выбирает.** Mixer никогда не решает, что сыграет следующим; Policy никогда не
ходит в сеть. Так Policy можно проверять тестами (`test/wave.test.js`) с подставным `random`.

То же разделение на Android: `data/WaveMixer.kt` + `data/WavePolicy.kt` (с `WavePolicyTest.kt`).
**Правите одно — правите оба** (и iOS, когда там появится полноценная волна).

## Как идёт один запрос

Окно: `api.wave.start()` → main `wave:start` → `WaveMixer.start()` → 8 треков.
Когда очередь заканчивается, `player.js` зовёт `api.wave.more(ids в очереди)` → `WaveMixer.more()`.

Внутри `batch()`:

1. **Лайки** (`libraries()`): `likedTracks(300)` каждого подключённого сервиса, кэш 2 минуты.
   Позиция в списке → `recency` 0…1 (новые лайки «свежее»).
2. **Рекомендации** (`recommendations()`), если кандидатов-нелайков мало или на каждый третий запрос:
   - Выбирается **затравка** — один свежий лайк (`recencyPick`, чем выше «Свежесть», тем свежее).
   - Яндекс: `waveStart(opts)` при первом запросе, потом `waveMore(ids)`. Плюс `similarTracks(затравка)`, если затравка из Яндекса.
   - VK: `recommendations()`. YT: `radio(затравка)`. SC: `related(затравка)` — если затравка из этого сервиса.
   - Все сервисы: поиск по исполнителю затравки (перенос вкуса между сервисами по открытым данным).
   - У каждого кандидата — `affinity` (тот же исполнитель, любимые исполнители, накопленный вкус `taste`) и `reason` (подпись «почему этот трек» в интерфейсе).
3. **Выбор**: `policy.select(candidates, { diversity, fresh, share, mood, recentIds, history })`.
4. Пусто → ещё раз рекомендации → снова выбор → иначе понятная ошибка.

`generation` и `ensure(s)`: если пользователь сменил настройки, пока шёл запрос, старый подбор
отменяется исключением — иначе в очередь приедут треки со старыми настройками.

## Настройки волны

| Настройка (`store.js`) | В окне | Что делает |
|------------------------|--------|-----------|
| `waveDiversity` | «Характер»: Всё / Любимое / Незнакомое / Популярное | Целевые доли категорий (`waveTargets`) |
| `waveFresh` 0…100 | «Свежесть» | Сколько недавних лайков против старых; насколько свежая затравка |
| `ytmShare` 0…100 | «Баланс источников» | Доля **не-Яндекса**. Историческое имя: когда-то был только YouTube |
| `waveMood` | «Настроение»: Бодрое / Весёлое / Спокойное / Грустное | Передаётся Яндексу как `settingMoodEnergy:<mood>` |

Все четыре синхронизируются между устройствами (`WAVE_KEYS`).

### Категории и квоты (`waveTargets`)

Каждый кандидат попадает в одну из трёх категорий:

- **recent** — лайк со свежестью ≥ 0.5;
- **library** — более старый лайк;
- **related** — не лайк (рекомендация).

`waveTargets(diversity, fresh)` возвращает целевые доли, например для «Всё» при свежести 60:
55% лайков (из них ~26% недавних) и 45% нового. «Незнакомое» — 100% related, лайки исключаются совсем.

`select()` для каждого слота считает **дефицит**: насколько категория и сервис отстают от своей доли
**за всю сессию** (не за пачку). Счёт = `5·дефицит категории + 1.5·дефицит сервиса + свежесть + 0.7·affinity + шум`.
Шум Гумбеля даёт разнообразие, но не перебивает квоты.

Дополнительно:

- одна запись из пяти сервисов — **одна группа** (`sameRecording`, ISRC) и считается один раз;
- последние 3 исполнителя не повторяются, если есть из чего выбрать;
- «слышал недавно» (`recentIds`, история) остывает внутри своей категории, а не выкидывает её целиком;
- дизлайк (`block`) — навсегда (хранится в `wave-profile.json`, до 500 штук).

### Вкус

`feedback(type, track, played)` на каждое событие плеера: дизлайк −3, лайк +2, пропуск раньше 30 с −1,
дослушал +1. Хранится по исполнителю в `state.taste` (−5…+5, затухание 0.95), файл `userData/wave-profile.json`.
События Яндекс-треков дополнительно уходят Яндексу (`waveFeedback`) — его rotor тоже учится.

## Настроение — тонкое место

**Настроение понимает только «Моя волна» Яндекса** (rotor с сидом `settingMoodEnergy`). Ни лайки,
ни радио YouTube, ни поиск по исполнителю не знают, «спокойный» ли трек.

Что из этого следует (исправлено в nightly 0.8 (103), в main ещё нет):

- При выбранном настроении другие источники **не подмешиваются**: кандидаты помечаются `moodOk`,
  в выбор идут только они.
- В `waveMore()` Яндексу отправляются **только его же треки** (`s.rotorIds`). Если отправить смешанную
  очередь, rotor «уплывает» от настроения — отсюда были джампстайл и хардтекк в «Спокойном».
- Без входа в Яндекс настроение фактически не работает — в интерфейсе это стоит честно показывать.

Идея на будущее: теги Last.fm (`chill`, `sad`, `energetic`) как настроение для любых сервисов. Не сделано.

### Баланс в крайних положениях

В main баланс «мягкий»: при 0% других сервисов кандидаты VK/YT всё равно могли проскочить, если Яндекс-кандидатов
не хватало. В nightly 0.8 (103) края жёсткие: 0% — только Яндекс, 100% — без Яндекса (если такие кандидаты есть).

## Своя волна Nyao (nightly, бета)

Задача: рекомендации для **любых** сервисов, а не только «Моя волна» Яндекса. Без токенов на сервере.

```
приложение: затравка — 14 свежих лайков + 8 дослушанных  ──►  POST /wave/mix (сервер Nyao)
сервер: Last.fm track.getsimilar, Deezer related/top     ──►  [{ artist, title, reason }]
приложение: findMatch в своих сервисах (Яндекс → VK → SC → YT), 4 потока параллельно
         ──► кандидаты с reason «Своя волна Nyao» → обычный WavePolicy
```

- Код: `server/src/wave-mix.js` (`waveMixer({ lastfmKey })`, кэш ответов на сутки), маршрут в `server/src/app.js`,
  клиент — `WaveMixer.nyaoCandidates()`; в `main.js` миксеру передаётся `nyao: { mix: body => cloud.request("POST", "/wave/mix", body) }` (вход в аккаунт Nyao не нужен).
- Ключ Last.fm — `LASTFM_KEY` на сервере (секрет `NYAO_LASTFM_KEY`). Пользователям ничего подключать не нужно.
- Настройка `waveNyao` (по умолчанию `true`). При выбранном настроении своя волна не используется.
- Сервер, задеплоенный из main, этого маршрута не знает — приложение тогда просто не получает кандидатов.

## Как отлаживать волну

- Подпись под треком в интерфейсе — это `waveReason`: «Недавний лайк», «Из любимого», «Рекомендация сервиса»,
  «Исполнитель из твоих лайков: …», «Моя волна Яндекса · по настроению». Первое, на что смотреть в жалобе.
- `test/wave.test.js` — добавьте случай «при таких кандидатах и настройках ожидаю такую долю», прежде чем менять формулу.
- `userData/wave-profile.json` можно удалить — вкус и дизлайки обнулятся.
- Яндекс сам по себе иногда даёт странное по «Спокойному» — сравните с официальным приложением, прежде чем чинить у нас.
