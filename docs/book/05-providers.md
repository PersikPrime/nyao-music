# 5. Музыкальные сервисы

## Провайдер — один класс на сервис

`src/main/providers/`:

| Файл | Класс | Как ходит в сервис |
|------|-------|--------------------|
| `yandex.js` | `YandexProvider` | OAuth-токен, `api.music.yandex.net`. Волна — через `/rotor/session/*` |
| `ytmusic.js` + `ytraw.js` | `YTMusicProvider` | cookies `music.youtube.com` (нужен `SAPISID`), «сырой» InnerTube в `ytraw.js` |
| `soundcloud.js` | `SoundCloudProvider` | `oauth_token` + публичный `client_id` (вытаскивается из скриптов сайта, `getClientId`) |
| `vk.js` | `VKProvider` | сессия окна входа VK: внутренние запросы сайта (`al_audio.php`) и токен веба (`webToken`) |
| `spotify.js` | `SpotifyProvider` | официальный Web API с PKCE, свой Client ID пользователя |

Создаются в `initProviders()` (`main.js`). Каждому передаётся свой `fetch`:
YouTube и SoundCloud — Node `fetch` (сеть Chromium подменяет заголовки), VK — `vkSessionFetch`
(запрос из сессии окна входа, с её cookies), Яндекс — обычный.

### Общий интерфейс (по факту, не формально)

Явного базового класса нет, но всё приложение рассчитывает на такие методы:

| Метод | Что вернуть | Есть у |
|-------|-------------|--------|
| `loggedIn` (свойство) | вошёл ли пользователь | все |
| `getAccount()` | `{ name, avatar, … }` | все |
| `search(q)` | `Track[]` | все |
| `likedTracks(limit)` | `Track[]`, **новые первыми** (на этом держится «свежесть» волны) | все |
| `playlists()` / `playlistTracks(id)` | плейлисты и их треки | все |
| `like(track, on)` | — | все |
| `streamUrl(srcId)` | прямая ссылка на звук (или данные для HLS) | ya, yt, sc, vk |
| `artist(id)`, `album(id)`, `searchArtist`, `searchAlbum` | страницы | ya, yt |
| `lyrics(id)` | текст | ya, yt |
| для волны: `waveStart/waveMore/waveFeedback`, `similarTracks` | — | ya |
| для волны: `radio(srcId)` / `related(srcId)` / `recommendations()` / `wavePool()` | — | yt / sc / vk |

Если провайдер чего-то не умеет — вызывающий код это проверяет (`if (p.related)`) или вызывает только
для нужного `source`. Новые методы добавляйте одинаковыми именами во все провайдеры, где это возможно.

### Формат трека

Каждый провайдер приводит ответ сервиса к одному виду (функция `mapTrack` в начале файла провайдера):

```js
{
  id: 'ya:12345',          // source:srcId — уникален во всём приложении
  source: 'ya', srcId: '12345',
  title, artist,           // artist — строка, несколько исполнителей через ', '
  artistId, album, albumId,
  duration,                // секунды
  cover,                   // URL картинки или '' (тогда шаблонная обложка)
  available,               // false — нельзя играть (регион, удалён)
  preview,                 // true — только 30 секунд (SoundCloud Go+, Spotify без Premium)
  explicit, isrc?          // isrc помогает склеивать один трек из разных сервисов
}
```

**Этот формат одинаков на ПК, Android (`data/Models.kt`, `Track`) и iOS (`Core/Models.swift`).**
Он же уходит на сервер (история, «сейчас играет», миксы). Добавляете поле — добавьте его на всех трёх
платформах или сделайте необязательным.

## Обёртки «не уронить экран»

В `main.js` почти все обращения к сервисам идут через:

- `safe(promise, fallback)` — ошибка превращается в `fallback` и строку в логе;
- `up(source)` — сервис не помечен «упавшим» (статус-страница, глава 7);
- `spSafe` — то же для Spotify (там отдельная история с Premium и лимитами).

Так обработчик `search` опрашивает 5 сервисов параллельно и показывает то, что успело ответить.

## Звук: `stream.js`

`StreamService.resolve(trackId)` по `source` вызывает `provider.streamUrl()`, кэширует ссылку до её
истечения и запоминает ошибки. Дальше обработчик `nyao://stream/…` (глава 3) отдаёт байты:

| Сервис | Что приходит | Что делаем |
|--------|-------------|-----------|
| Яндекс | mp3/AAC, подписанная ссылка (`signDownload`) | отдаём как есть, с Range |
| YouTube | адаптивный аудиопоток | качаем кусками по 4 МБ (`chunkRange`), при 403 пробуем другой клиент InnerTube (`failedClients`) |
| SoundCloud | HLS (m3u8) | `downloadHls()` склеивает сегменты целиком, держим несколько последних в памяти |
| VK | HLS из MPEG-TS, сегменты зашифрованы AES-128 | `downloadHls()` + `demuxTs()` вынимает аудио из TS |

Трек не играет совсем → main ищет копию в другом сервисе (`findMatch`) и шлёт окну
`stream:substitute` — плеер незаметно заменяет трек в очереди.

## «Тот же трек в другом сервисе»: `match.js`

`findMatch(track, search, { minScore })`:

1. Строит запрос (`searchQuery`): исполнитель + название без «(feat …)», «Remastered» и т. п.
2. Ищет через переданную функцию `search` (любой провайдер).
3. Оценивает каждый результат `similarity()`: нормализация (`norm`, ё→е, транслит `translit`),
   сходство токенов названия и исполнителей, длительность, версия записи (`recordingVersion`:
   live / remix / acoustic не путаем с оригиналом).
4. Возвращает лучший результат, если он выше порога. Обычно 0.62; для замены звука — 0.85.

Используется в переносе плейлистов, замене недоступного трека, Spotify без Premium, своей волне Nyao,
«Слушать вместе» (у гостя другой набор сервисов). Покрыт тестами в `test/services.test.js` — правите
`similarity` — гоняйте `npm test`.

## Поиск

Обработчик `search` в `main.js` опрашивает все сервисы сразу и возвращает
`{ ya, yt, sc, vk, sp, artists, albums }`. Склейку и ранжирование делает окно: `src/renderer/search.js`
(`normName`, «лучший результат» — если запрос похож на имя исполнителя, его треки идут первыми).
Логика чистая, без DOM — её легко проверить отдельно (тестов пока нет, хороший первый вклад).

## Тексты песен: `lyrics.js`

Цепочка источников `findLyricsChain()`; порядок и включённость — настройка `lyricsOrder`
(синхронизируется между устройствами). Источники (`LYRICS_PROVIDERS`):

| id | Откуда |
|----|--------|
| `ya` | Яндекс (если трек из Яндекса или найден там через `matchYa`) |
| `nyao` | LyricLabs — наш сервис, построчно и **пословно** (караоке) |
| `lrclib` | lrclib.net — открытая база синхронизированных текстов |
| `ytm` | YouTube Music (обычно без таймингов) |

`lyricsWordsFirst` — сначала искать пословную разметку, даже если источник ниже по списку.
Форматы: `parseLrc()` (строки `[mm:ss.xx]`) и `parseWordLrc()` (`<mm:ss.xx>` внутри строки).

## Мелочи, о которых стоит знать

- **Лайки SoundCloud** иногда не проходят (капча, лимиты) — их держит очередь `pending-likes.js`
  (повторы до 5 раз, до 14 дней) и досылает позже.
- **VK** выдаёт «битые» ответы при истёкшей сессии — провайдер тихо продлевает её (`refreshSession`),
  сырые ответы при сбоях пишет в `userData/vk-debug.log` (через `safeDiagnostic`).
- **YouTube** кэширует часть данных в `userData/yt-cache`.
- **Spotify** — два движка: Web Playback SDK в скрытом окне (нужен Widevine — отсюда сборка Electron от castlabs)
  и экспериментальный `librespot` (Rust, `native/librespot/`).

## Как добавить новый сервис (кратко)

Пошагово — в главе 11. Суть: провайдер с методами из таблицы выше → `initProviders()` → `streamUrl`
в `StreamService` → вход в `auth.js` → статус и значок в окне → источник в волне → то же на Android и iOS.
