# 10. Версии, ветки, сборки, релизы

## Ветки

| Ветка | Что | Канал в `version.json` | Релиз |
|-------|-----|------------------------|-------|
| `main` | То, что получают все | нет поля `channel` | `v0.8.N` — обычный релиз, его видят центр обновлений и зеркало сервера |
| `dev` | Почти готовое, тестирует узкий круг | `"channel": "dev"` | `v0.8.N-dev` — пререлиз |
| `nightly` | Эксперименты (своя волна, castlabs, librespot) | `"channel": "nightly"` | `v0.8.N-nightly` — пререлиз |
| любая другая | Проверочные сборки | — | Релиза нет, файлы — в артефактах запуска Actions |

Изменения идут обычно `nightly → dev → main` (или сразу `dev → main`). **При переносе в main уберите `channel`
из `version.json`**, иначе в main уедет пререлиз (так уже было — глава 12).

## Версия: `version.json`

```json
{ "name": "0.8", "build": 101, "channel": "dev" }
```

- Один файл на все платформы: ПК (`package.json` → `0.8.101`), Android (`versionCode = build`), iOS (CI подставляет).
- `build` — целое число, растёт всегда. Публично версия пишется «0.8 (101)».
- Необязательное `displayVersion` — публичное имя патча (`0.8.97.1`), подробно в `docs/patch-releases.md`.

**Порядок выпуска:**

```bash
# 1. поправить version.json (или: node scripts/bump.mjs — сам увеличит build; --patch — патч-нумерация)
node scripts/bump.mjs --sync        # 2. переносит версию в package.json и имена файлов
# 3. заметки к релизу: .github/notes/v0.8.102-dev.md (имя = тег)
git commit -am "dev 0.8 (102): …" && git push
```

Заметки (`.github/notes/<тег>.md`) показываются в центре обновлений приложения — пишите их для людей, не для разработчиков.
Если файла нет, релиз получит безликое описание «Сборка … из коммита …».

## Что собирается и когда

Сборки запускаются **только от изменений в своих папках** (`paths` в workflow):

| Workflow | Когда | Что делает |
|----------|-------|-----------|
| `desktop.yml` | `src/**`, `test/**`, `build/**`, `native/**`, `package*.json`, `version.json` — любая ветка | Windows (NSIS + ZIP), macOS (DMG arm64 + x64), пакет горячего обновления `.nui` |
| `android.yml` | `android/**`, `version.json` | Тесты + подписанный APK |
| `ios.yml` | `ios/**`, `version.json` | Неподписанный IPA + `sidestore.json` |
| `server.yml` | `server/**` в `main`/`nightly` | Тесты и деплой сервера (глава 7) |
| `legacy.yml`, `librespot.yml` | свои папки | Nyao Legacy, нативный Spotify |
| `maintenance.yml`, `ops.yml`, `server-diag.yml` | вручную | Техработы, перезапуск/логи сервера, диагностика |
| `claude-tg.yml` | вручную | Сообщение в Telegram-группу проекта (об апдейтах) |

Правка только в `docs/` не запускает ничего. Правка `version.json` запускает **все** сборки приложений.

Файлы всех платформ складываются в **один** релиз с тегом из `version.json` (`.github/scripts/release-upload.sh`:
создаёт релиз, если его ещё нет, и докладывает файлы).

### Подписи

- **Windows/macOS**: Electron от castlabs с Widevine (для Spotify). Сборка проходит VMP-подпись в castlabs EVS
  (секреты `NYAO_EVS_*`) — без неё Spotify не играет. Подписи разработчика Apple нет: на Mac приложение ad-hoc,
  пользователю нужно разрешить запуск в настройках безопасности.
- **Android**: ключ `NYAO_KEYSTORE_*`. Потеряете ключ — обновления поверх перестанут ставиться у всех.
- **Горячие обновления**: Ed25519, приватный ключ `NYAO_HOT_KEY`, публичный — `src/main/hot-key.pem`.
- **iOS**: подписывает устройство пользователя (SideStore).
- **Ключи Last.fm** кладутся в `src/main/lastfm-keys.json` прямо в CI — в git их нет.

## Горячие обновления ПК (`.nui`)

ПК умеет обновлять свой JS без установщика:

1. CI: `node scripts/hot-bundle.mjs --compat` считает «совместимость» (версия Electron, нативные библиотеки, ABI помощника),
   потом `hot-bundle.mjs` упаковывает `src/**`, `version.json`, `package.json` в `NyaoMusic-…-app-<COMPAT>.nui` + `.sig`.
2. Приложение (`hot.js`) видит новый релиз, находит `.nui` со **своим** COMPAT, проверяет подпись и распаковывает в `userData/hot/<build>/`.
3. Следующий запуск грузит код оттуда. Сломалось — «Вернуть версию из установщика».

Когда горячее обновление **не** подойдёт и нужен полный установщик: смена версии Electron, зависимостей
с нативным кодом, `native/`, ABI помощника, `build/`, `package.json` с новыми зависимостями.

## Обязательное обновление

`MIN_BUILD` на сервере (переменная `NYAO_MIN_BUILD`): приложения старее получают `426` на синхронизацию и
экран «обновись». Повышайте, только когда старые сборки реально ломают данные (например, меняется формат на сервере).

## Чеклист релиза в main

- [ ] Всё нужное влито, `npm test`, `cd server && npm test` зелёные.
- [ ] В `version.json` **нет** `channel`, `build` больше последнего.
- [ ] `node scripts/bump.mjs --sync`.
- [ ] `.github/notes/v0.8.N.md` написан.
- [ ] Если сервер в nightly ушёл вперёд — его изменения тоже в main (иначе деплой из main откатит сервер).
- [ ] После сборки: скачать и запустить хотя бы установщик Windows и APK.
