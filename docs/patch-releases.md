# Патчи и быстрые обновления

`node scripts/bump.mjs --patch` увеличивает служебный целочисленный `build`,
но сохраняет базу публичной версии: 0.8.97 → 0.8.97.1 → 0.8.97.2.
`displayVersion` в version.json задаёт публичную версию в приложении, Android,
названии релиза и именах файлов. package.json остаётся валидным semver со служебным build.
Обычный вызов bump без --patch возвращает стандартную нумерацию; --sync ничего не увеличивает.

Тег релиза сохраняет старый формат v0.8.BUILD-nightly. Старые клиенты и серверное
зеркало распознают только его и сравнивают целые номера. В именах патч-файлов
есть публичная версия и служебная версия: это сохраняет фильтрацию файлов старым
зеркалом, даже когда в том же релизе появляется Android APK.
Например, публичный патч 0.8.97.1 имеет build 98, тег v0.8.98-nightly и файл
NyaoMusic-0.8.97.1-build-0.8.98-app-COMPAT.nui.

Формат `.nui` и подпись не меняются. Старый загрузчик видит обычную сборку 98,
а обновлённый интерфейс читает публичное имя из version.json. Не нужно менять
native ABI ради JS-правок. Native ABI повышается только при обязательной замене
нативных компонентов: такое обновление требует полного установщика.

0.8.97.1 сохраняет native ABI 2, поэтому ставится через `.nui` на полный
установщик 0.8.97 с helper 2. Установщикам 0.8.96 и старше сначала нужен полный
установщик с ABI 2. Ключи подписи остаются в GitHub Secrets.

Публичный 0.8.100 зарезервирован для полноценного релиза main. Для промежуточных
исправлений используй --patch; новое публичное имя не требует смены нативных компонентов.
