# Сайт Nyao Music

Лендинг music.withnyao.app с загрузками. Node.js + Express + EJS, без сборки и без фронтенд-библиотек.

На сервере работает отдельным контейнером `site` (см. `server/docker-compose.yml`). Caddy отдаёт ему корень
music.withnyao.app, а ссылки «Поделиться» (`/share/…`, `/join/…`), `/.well-known/…` и файлы `/dl/…` по-прежнему
обслуживает API. Выкатывается вместе с сервером при push в `main` или `nightly`.

## Запуск

```bash
npm install
npm start          # http://localhost:3000
npm run dev        # то же, с перезапуском при правках
```

Нужен Node.js 18 или новее.

## Настройка

Всё в `config.js`: ссылки (GitHub, Telegram, документация), тексты платформ, запасные номера версий.
Ссылки на Telegram и сайт студии пока пустые (`#`) — впиши свои.

Переменные окружения:

| Переменная | Зачем |
| --- | --- |
| `PORT` | порт, по умолчанию 3000 |
| `SITE_URL` | адрес сайта для sitemap и превью ссылок, например `https://music.example.com` |
| `RELEASES_API` | адрес API Nyao Music; на сервере `http://api:8080`. Тогда релизы и файлы берутся из зеркала сервера |
| `GITHUB_REPO` | без `RELEASES_API` — репозиторий с релизами, по умолчанию `PersikPrime/nyao-music` |
| `GITHUB_TOKEN` | нужен, только если репозиторий закрыт или упираешься в лимит GitHub. Держи в окружении, не в коде |

## Как работают загрузки

Сайт раз в 10 минут спрашивает у GitHub список релизов и берёт оттуда свежую стабильную версию и свежую Red
(релизы с `nightly` в теге или помеченные как pre-release). Файлы подбираются по расширению: `.exe`, `.dmg`, `.apk`, `.ipa`.

- `/download/stable/win`, `/download/red/android` и т. д. — перенаправляют на файл.
- Если GitHub недоступен или файла нет — на страницу релиза, а если и её нет — на общий список релизов. Сайт при этом не падает.
- `/api/releases` — то же самое в JSON (версии, даты, имена и размеры файлов).

Важно: если репозиторий закрытый, ссылки на файлы у гостей не откроются даже с токеном на сервере —
для публичных загрузок релизы должны быть в открытом репозитории.

## Что где

```
server.js            маршруты, заголовки безопасности, определение платформы гостя
config.js            ссылки и тексты
lib/shapes.js        печенька и объёмные значки (SVG считается на сервере)
lib/releases.js      релизы с GitHub, с кэшем
views/index.ejs      страница
views/404.ejs
public/css/site.css  стили
public/js/site.js    движение: появление при прокрутке, сцена за курсором, карточки, пример полного экрана, вкладки
public/js/boot.js    одна строка в <head>, чтобы блоки не мигали до загрузки скриптов
```

## Про движение

- Всё, что следует за курсором или прокруткой, идёт через один цикл `requestAnimationFrame` с плавным догоном —
  без рывков, и цикл останавливается, когда двигать нечего.
- Анимируются только `transform` и `opacity`.
- При системной настройке «уменьшить движение» всё выключается, содержимое остаётся.
- На телефонах (нет курсора) сцена на первом экране сама медленно покачивается, наклон карточек отключён.

## Выкладка

Любой хостинг с Node.js. Пример с PM2 за nginx:

```bash
PORT=3000 SITE_URL=https://music.example.com pm2 start server.js --name nyao-site
```

В nginx — обычный `proxy_pass http://127.0.0.1:3000;` с заголовком `X-Forwarded-Proto`.

Шрифты (Onest, Unbounded) грузятся с Google Fonts. Если нужно без внешних запросов — положи их в `public/fonts`
и замени `<link>` в `views/*.ejs` на свой `@font-face`, а в `server.js` убери Google из Content-Security-Policy.
